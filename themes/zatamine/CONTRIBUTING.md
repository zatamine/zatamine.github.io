# Contributing to Zatamine Theme

Thank you for your interest in contributing to the Zatamine Hugo theme! This document outlines the contribution process and best practices.

## Code of Conduct

By participating in this project, you are expected to uphold our Code of Conduct. Please report unacceptable behavior to [maintainer email].

## How to Contribute

### Reporting Issues

- Before submitting an issue, please search existing issues to avoid duplicates
- Include detailed information about the problem
- Provide steps to reproduce the issue
- Specify your Hugo version and browser/environment details

### Suggesting Features

- Open a discussion issue first to gauge interest
- Clearly describe the feature and its use case
- Explain how it would benefit users of the theme

### Pull Request Process

1. Fork the repository
2. Create a feature branch (`git checkout -b feature/your-feature-name`)
3. Make your changes following the style guide below
4. Write tests for new functionality if applicable
5. Update documentation as needed
6. Submit a pull request with a clear description

## Development Guidelines

### Code Style

- Follow existing code patterns in the theme
- Maintain consistency in CSS class naming (BEM methodology preferred)
- Use semantic HTML elements appropriately
- Ensure JavaScript is well-commented and follows modern ES6+ standards

### Testing

- Test changes across different screen sizes
- Verify dark mode functionality works correctly
- Check that all interactive elements work properly
- Validate that the theme builds without errors

### Documentation

- Update README.md if the change affects user-facing features
- Add comments to complex code sections
- Document any new configuration options

## Branching Strategy

- `main` branch contains stable releases
- Feature branches should be created for new functionality
- Hotfixes should be branched from `main`

## Pull Request Requirements

- All tests must pass
- Code must follow the established style guide
- Changes must be backwards compatible where possible
- Include a clear description of the problem and solution
- Add documentation updates if needed
